# Anatomy V4: Causal Engineering Exhibition

The two enterprise cases remain anonymized. All simulation examples, PR IDs, code files, status changes and outputs are fictional and stored in browser React state.

Evidence distinctions:
- Team adoption within under a month: delivered engineering-team account, not independently audited company-wide adoption.
- Banking PoC aggregates: 168 reported human hours; 173 generated UI components; 91 represented functions; 66 contract operations; 22,995 source-linked references; 4,338 file comparisons. No deployed microfrontend count or established functional parity. Publication clearance still required.
- The RUN FIXTURE interactive simulation is a deterministic teaching mechanism. It does not run models, analyze real customer code or execute CI.

Execution gates:
- Six sequential stages per machine; every stage is checked before marking it passed.
- Three independent quality toggles per machine, each causing BLOCKED at a specific stage if disabled.
- Remaining stages stay waiting after the failure; reconnecting a guard resets the model.
- Two fictional fixtures with distinct source-to-evidence artifact chains.
- Executive / Architecture / Engineering explanation modes.
- Guided tour navigates the diagram and does not claim to execute a real workflow.
- Anatomy V3 physical apparatus retained, with assembly / exploded / signal-flow controls.
- New five-principle master atlas explains conceptual correspondences among four domains, not a universal shared runtime.

Release gate:
1. Run pnpm build and scripts/anatomy-v4-check.mjs.
2. In browser verify complete vs blocked, every gate, fixture changes, stage selection, tour, three modes, and accessibility.
3. Check 390px, 768px and 1440px viewport width and reduced-motion preference.
4. Confirm route /anatomy, homepage, experience, banking and cybersecurity case pages return 200.
5. Keep PR draft and no merge until design and disclosure approval.
